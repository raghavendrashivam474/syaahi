# Detailed Bug Breakdown

## Bug 1: The Walkthrough Infinite-Width Crash (7 Debug Attempts)

### Symptom
Tapping the **?** help button on the feed screen triggered an immediate layout exception:
```text
BoxConstraints forces an infinite width.
The offending constraints were: BoxConstraints(w=Infinity, 44.0<=h<=Infinity)
The relevant error-causing widget was: ElevatedButton

```

### Investigation & Failed Approaches

* **Attempt 1 (Transparent Dialog):** Originally designed as a `Dialog`. `backgroundColor: Colors.transparent` rendered the card invisible on the dark theme (`midnightBase`).
* **Attempt 2 (Opaque Dialog):** Changed background to `midnightBase`. Exposed the `BoxConstraints(w=Infinity)` crash.
* **Attempt 3 (Inner maxWidth Constraints):** Wrapped dialog content in `Container(constraints: BoxConstraints(maxWidth: 480))`. The `Dialog` widget's internal `Material`/`ConstrainedBox` wrapper consumed constraints prior to reaching the inner container, leaving `Row` children unbounded.
* **Attempt 4 (Center + ConstrainedBox):** Attempted to replace `Dialog` with custom `Center` → `ConstrainedBox` overlay. PowerShell multi-line `.Replace()` silently failed due to CRLF vs LF line-ending mismatches.
* **Attempt 5 (Full File Rewrite):** Concatenation artifact left duplicate nested `Dialog` wrappers inside the file.
* **Attempt 6 (Bottom Sheet Rebuild):** Rebuilt as `showModalBottomSheet`. Removed `isScrollControlled: true` and added `Expanded` wrappers. The crash persisted on `ElevatedButton` at line 147:15.
* **Attempt 7 (Targeted Regex/Replace):** Silently failed due to CRLF mismatches.

### Root Cause Discovery

`Select-String` across the file confirmed `minimumSize` and `double.infinity` were nowhere in `onboarding_walkthrough.dart`.

The constraint `Size(double.infinity, 44)` was inherited globally from the application's `ElevatedButtonThemeData` in the global theme configuration. An `ElevatedButton` inheriting infinite width minimums placed inside a `Row` (which passes unconstrained width to un-expanded children) creates an unsatisfiable constraint `BoxConstraints(w=Infinity)`. Static analysis (`flutter analyze`) cannot catch this as it is a runtime layout evaluation error.

### Resolution

Explicitly overrode `minimumSize` on the walkthrough `ElevatedButton`:

```dart
ElevatedButton(
  style: ElevatedButton.styleFrom(
    minimumSize: const Size(0, 44), // Overrides global theme's Size(double.infinity, 44)
  ),
  onPressed: () { ... },
  child: Text(isLast ? 'Get Started' : 'Next'),
)

```

## Bug 2: Discovery Screen Direct URL Back-Navigation

### Symptom

Navigating directly to `/discover` via browser URL and clicking the AppBar back button threw:

```text
GoError: no routes to pop

```

### Root Cause

`context.pop()` was called unconditionally. When `/discover` is the root route of a browser session, the GoRouter stack is empty (`canPop() == false`).

### Resolution

Guarded back-navigation with stack checking:

```dart
onPressed: () {
  if (GoRouter.of(context).canPop()) {
    context.pop();
  } else {
    context.go('/welcome');
  }
}

```

## Bug 3: Feed Screen File Restoration

### Symptom

After the branch merge, `feed_screen.dart` lacked the `onboarding_walkthrough.dart` import and the help button was missing.

### Root Cause

`git merge -X theirs` selected the incoming branch version wholesale, discarding the parallel work on `feed_screen.dart`.

### Resolution

Checked out known-good commit state from tag:

```powershell
git checkout v-UX-07 -- lib/features/poems/presentation/feed_screen.dart

```

Re-applied the walkthrough import and help `IconButton`.

## Bug 4: Duplicate Help Icon in Feed AppBar

### Symptom

Visual inspection of the feed screen top bar revealed two **?** icons:
`[Search] [Filter] [Bell] [Heart] [?] [Profile] [Logout] [?]`

### Root Cause

During the re-application of the walkthrough button in `feed_screen.dart`, one `IconButton` was placed in logical position (index 4, between Heart and Profile) and a second `IconButton` with `color: SyaahiColors.textMuted` was appended at the end of the `actions` array after Logout.

### Resolution

Removed the trailing duplicate `IconButton` from `AppBar.actions`, keeping the single `IconButton` before Profile and Logout to maintain standard AppBar action hierarchy.

## Infrastructure & Technical Learnings

* **Theme-Inherited Constraints are Invisible to Static Analyzers:** Theme data can inject fatal layout constraints (`minimumSize: Size(double.infinity, 44)`) into child widgets. Always search global theme definitions when encountering `BoxConstraints(w=Infinity)` errors inside flex layouts.
* **PowerShell Multi-line File Operations:** Standard PowerShell `.Replace()` methods fail silently when multi-line pattern match targets differ in line-ending convention (CRLF vs LF). Use `[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))` for complete file updates.
* **Hot Restart vs Hot Reload for Layout Engine Testing:** Hot reload (`r`) preserves state and can retain stale widget subtrees. Always use Hot Restart (`R`) when testing fundamental layout hierarchy changes.
